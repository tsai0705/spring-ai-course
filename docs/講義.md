# Spring AI 入門實作課

本專案使用 Spring AI 2.0.1 + Spring Boot 4.1.1 + Java 21，模型跑在你電腦上的 Ollama。請先確認是否完成《課前準備.md》

## 1. 啟動專案

二選一：

- IntelliJ：打開 `SpringAiCourseApplication`，按 main 方法旁的綠色三角形執行。
- 指令：在專案根目錄執行（macOS/Linux 用 `./mvnw spring-boot:run`）：

```bash
.\mvnw.cmd spring-boot:run
```

看到 console 出現 `Started SpringAiCourseApplication` 就代表啟動成功，服務在 `http://localhost:8080`。啟動時 Lab 4 會讀取請假規則並呼叫 embedding 模型，所以 Ollama 沒開或模型沒下載會啟動失敗。

## 2. 概念速覽

| 功能 | 一句說明 | 主要元件 | 這堂課實作 |
|---|---|---|---|
| ChatClient | 呼叫聊天模型的流暢 API（`defaultSystem` 設定每次請求都帶上的 system prompt） | `ChatClient`、`ChatClient.Builder` | 是（Lab 1） |
| Structured Output | 把模型回應轉成 Java 物件 | `.entity()`、`BeanOutputConverter` | 是（Lab 1） |
| Tool Calling | 讓模型呼叫你寫的 Java 方法 | `@Tool`、`.tools()` | 是（Lab 2） |
| RAG | 先檢索文件再讓模型回答 | `VectorStore`、`EmbeddingModel`、`QuestionAnswerAdvisor` | 是（Lab 4） |
| Chat Memory | 讓模型記得先前對話 | `ChatMemory`、`MessageWindowChatMemory` | 是（Lab 3） |
| Advisors | 請求前後的攔截器 | `Advisor`、`SimpleLoggerAdvisor` | 是（Lab 3、4） |
| MCP | 標準化的工具與資源連接協定 | MCP Client / Server starter | 否 |
| 多模態 | 輸入圖片、音訊等 | `Media`、`UserMessage` | 否 |
| Evaluation | 評估回答品質與幻覺 | `Evaluator`、`RelevancyEvaluator` | 否 |
| Observability | 用 Micrometer 追蹤呼叫與 token | Micrometer Observation | 否 |
| Agent 模式 | 以工作流或迴圈組合多次模型呼叫 | Chain、Routing、Orchestrator 等模式 | 否 |

## 3. 實作

每個 Lab 都是「先跑沒加功能的版本，看結果，再跑加了功能的版本，比較差異」。驗證時直接用瀏覽器開網址，網址裡可以直接寫中文。每次回答都可能不同，你看到的內容只會「類似」下面描述的結果。

### Lab 1：ChatClient 與結構化輸出

**目標**：用 ChatClient 問答，並讓模型回傳可直接使用的 Java 物件。

**用到的元件**：`ChatClient`、`.entity()`、`record Book`

**步驟**

1. 打開 `src/main/java/com/example/springaicourse/lab1/ChatController.java`，ChatClient 由自動設定好的 Builder 建出：

```java
public ChatController(ChatClient.Builder builder) {
    this.chatClient = builder
            // 小模型預設常用簡體中文回答，用 system prompt 固定語言
            .defaultSystem("請用繁體中文回答")
            .build();
}
```

`defaultSystem` 設定的 system prompt 會附在這個 ChatClient 之後的每一次請求。3B 小模型預設常用簡體中文回答，所以四個 Lab 的 ChatClient 都加了這一行。

2. `/lab1/chat` 是最基本的呼叫鏈：

```java
return chatClient.prompt()   // 開始組一個請求
        .user(q)             // 使用者訊息
        .call()              // 同步呼叫模型（串流用 .stream()）
        .content();          // 只取回應文字
```

3. `/lab1/book-text` 只拿到自由文字，`/lab1/book` 加上 `.entity()` 後拿到 `List<Book>`：

```java
.entity(new ParameterizedTypeReference<List<Book>>() {
});
```

`Book` 定義在 `lab1/Book.java`：

```java
public record Book(String title, String author) {
}
```

**驗證**

依序用瀏覽器開下面三個網址：

1. `http://localhost:8080/lab1/chat?q=用一句話介紹 Spring AI`
2. `http://localhost:8080/lab1/book-text?topic=Java`
3. `http://localhost:8080/lab1/book?topic=Java`

**預期看到什麼**

- `chat`：一句繁體中文的回答。
- `book-text`：一大段自由排版的文字，每次格式都可能不同，程式很難解析。
- `book`：瀏覽器直接顯示 JSON 陣列，類似 `[{"title":"...","author":"..."}, ...]`，共 3 筆。

**常見問題**

- 瀏覽器顯示 Whitelabel Error Page 或連不上：確認專案已啟動，且網址的路徑與參數名稱沒打錯。
- 啟動或呼叫時出現 connection refused：Ollama 沒啟動。
- `book` 偶爾回 500 或解析錯誤：3B 小模型偶爾輸出格式不對，重打一次即可。
- 第一次呼叫很慢：模型正在載入記憶體，之後會快很多。

### Lab 2：Tool Calling

**目標**：讓模型透過 `@Tool` 取得它自己不知道的即時資訊。

**用到的元件**：`@Tool`、`.tools()`

**步驟**

1. `lab2/TimeTools.java` 把一個 Java 方法標成工具，`description` 是模型判斷何時呼叫的依據：

```java
@Tool(description = "取得目前的日期與時間（台北時區 Asia/Taipei）")
public String getCurrentTime() {
    return ZonedDateTime.now(ZoneId.of("Asia/Taipei"))
            .format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss z"));
}
```

2. `lab2/ToolController.java` 的 `/lab2/with-tool` 比 `/lab2/no-tool` 多一行 `.tools(timeTools)`：

```java
return chatClient.prompt()
        .user(q)
        // .tools() 把物件裡所有 @Tool 方法註冊給這次請求；
        // 模型決定要呼叫時，Spring AI 會執行方法並把結果送回模型產生最終答案
        .tools(timeTools)
        .call()
        .content();
```

**驗證**

依序用瀏覽器開下面兩個網址：

1. `http://localhost:8080/lab2/no-tool?q=現在幾點？`
2. `http://localhost:8080/lab2/with-tool?q=現在幾點？`

**預期看到什麼**

- `no-tool`：模型答不出目前的時間，或反過來要你告訴它現在幾點。
- `with-tool`：回答出目前的日期與時間（台北時區），console 可以看到工具被呼叫。

**常見問題**

- `with-tool` 沒有呼叫工具：3B 模型偶爾判斷失誤，問題寫得更明確，例如「請告訴我現在的日期與時間」。
- 時間差 8 小時：確認 `TimeTools` 有指定 `Asia/Taipei`。

### Lab 3：Chat Memory 與 Advisor

**目標**：讓模型記得同一位使用者先前說過的話，並用 Advisor 觀察實際送出的 prompt。

**用到的元件**：`MessageChatMemoryAdvisor`、`MessageWindowChatMemory`、`SimpleLoggerAdvisor`、`conversationId`

**步驟**

1. `lab3/MemoryController.java` 建立只保留最近 10 則訊息的記憶：

```java
ChatMemory chatMemory = MessageWindowChatMemory.builder()
        .maxMessages(10)
        .build();
```

2. 加了功能的 client 掛上記憶 Advisor 與 logger Advisor：

```java
this.memoryClient = builder.clone()
        // 小模型預設常用簡體中文回答，用 system prompt 固定語言
        .defaultSystem("請用繁體中文回答")
        .defaultAdvisors(
                MessageChatMemoryAdvisor.builder(chatMemory).build(),
                new SimpleLoggerAdvisor())
        .build();
```

3. 每次請求用 `conversationId` 區分使用者：

```java
.advisors(a -> a.param(ChatMemory.CONVERSATION_ID, id))
```

4. `application.yml` 開 DEBUG，`SimpleLoggerAdvisor` 才會印出內容：

```yaml
logging:
  level:
    # SimpleLoggerAdvisor 用 DEBUG 等級印出請求與回應（Lab 3 觀察用）
    org.springframework.ai.chat.client.advisor: DEBUG
```

**驗證**

請照順序，用瀏覽器開下面的網址：

1. `http://localhost:8080/lab3/no-memory?q=我叫小明`
2. `http://localhost:8080/lab3/no-memory?q=我叫什麼名字？`
3. `http://localhost:8080/lab3/with-memory?id=s1&q=我叫小明`
4. `http://localhost:8080/lab3/with-memory?id=s1&q=我叫什麼名字？`
5. `http://localhost:8080/lab3/with-memory?id=s2&q=我叫什麼名字？`

**預期看到什麼**

- 第 2 步（`no-memory`）：模型不知道你叫什麼名字。
- 第 4 步（`with-memory`，同一個 `id=s1`）：大致會答出「小明」。
- 第 5 步（換成 `id=s2`）：模型不知道，因為這是另一個對話。
- console 的 DEBUG log 可以看到第 4 步請求的 prompt 裡帶有先前的對話。

**常見問題**

- 重啟後記憶消失：記憶存在 JVM 記憶體裡，這是預期行為。
- console 沒有 log：確認 `application.yml` 的 logger 名稱沒有被改動。

### Lab 4：RAG

**目標**：讓模型根據公司內部文件回答，而不是憑空猜。

**用到的元件**：`SimpleVectorStore`、`EmbeddingModel`、`TokenTextSplitter`、`QuestionAnswerAdvisor`

**步驟**

1. 文件在 `src/main/resources/docs/leave-policy.txt`（虛構的「範例科技」請假規則）。
2. `lab4/RagConfig.java` 啟動時讀檔、切塊、存入向量庫：

```java
SimpleVectorStore store = SimpleVectorStore.builder(embeddingModel).build();

// 讀檔成 Document
List<Document> documents = new TextReader(policy).get();

// 切成小塊：整份文件塞進 prompt 太長，切塊後只取最相關的幾塊
List<Document> chunks = new TokenTextSplitter().apply(documents);

// add 會對每個區塊呼叫 embedding 模型算出向量，再存進向量庫
store.add(chunks);
```

3. `lab4/RagController.java` 加了功能的 client 掛上 `QuestionAnswerAdvisor`：

```java
this.ragClient = builder.clone()
        .defaultSystem("請用繁體中文回答")
        .defaultAdvisors(QuestionAnswerAdvisor.builder(vectorStore).build())
        .build();
```

**驗證**

依序用瀏覽器開下面三個網址：

1. `http://localhost:8080/lab4/no-rag?q=特休要提前幾天申請？`
2. `http://localhost:8080/lab4/with-rag?q=特休要提前幾天申請？`
3. `http://localhost:8080/lab4/with-rag?q=病假超過幾天要附證明？`

**預期看到什麼**

- `no-rag`：回答泛泛而談或亂猜，例如建議提前一週。
- `with-rag`：特休答出提前 3 個工作天，與 `leave-policy.txt` 一致；病假問題大致會答出 2 天。
- 沒有 RAG 時，模型會一本正經地亂講。例如問它 Spring AI 是什麼，3B 小模型曾經回答成其他公司的產品。這就是需要 RAG 把正確資料交給模型的原因。

**常見問題**

- 啟動時報 embedding 錯誤：確認有 `ollama pull nomic-embed-text`。
- `with-rag` 答得不精準：3B 模型偶爾漏看段落，換個問法再試，或在 console 開 DEBUG 看檢索到哪些段落。
- 改了 `leave-policy.txt` 沒生效：向量庫在啟動時建立，需重啟。

## 4. 收尾

今天沒做的功能，你之後可以從官方文件延伸：

- MCP：用標準協定連接外部工具與資料來源，Spring AI 提供 MCP Client 與 Server。文件：https://docs.spring.io/spring-ai/reference/api/mcp/mcp-overview.html
- 多模態：訊息可以附上圖片、音訊等媒體，由支援的模型處理。文件：https://docs.spring.io/spring-ai/reference/api/multimodality.html
- Evaluation：用 Evaluator 檢查回答是否與檢索內容相關、有沒有幻覺。文件：https://docs.spring.io/spring-ai/reference/api/testing.html
- Observability：整合 Micrometer，記錄呼叫次數、耗時與 token 用量。文件：https://docs.spring.io/spring-ai/reference/observability/index.html
- Agent 模式：用 Chain、Routing 等工作流把多次模型呼叫組成較複雜的流程。文件：https://docs.spring.io/spring-ai/reference/api/effective-agents.html

其他功能請見官方文件首頁：https://docs.spring.io/spring-ai/reference/
